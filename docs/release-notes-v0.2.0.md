# forum-rag v0.2.0

**面向量化研究的本地检索与证据知识层：从「能搜到」到「能核查」。**

本次发布汇总了两个长期分支（`lody/semantic-performance`、`lody/task-evidence-performance`）的改动，是一次架构级收敛：检索从「无命中也会返回无关帖子」的宽召回实现，收敛为以本地 SQLite 词法检索为核心、返回可核查原文证据的轻量工具；知识层从「自动发布」改为「证据审核 + 来源版本校验」；同时完成官方 MCP Python SDK 2.x 升级与后台进程资源治理。

- 相关 PR：[#2](https://github.com/BeastOrange/forum-rag/pull/2)（已合并）、[#3](https://github.com/BeastOrange/forum-rag/pull/3)
- 基础候选：`5e304772cc3deb00730a9b1c782d632f8c1343cf`；进程退出竞态修复：`435876e`；最终内容以 `v0.2.0` 标签为准
- 版本：`0.1.0` → `0.2.0`（首个正式打标发布）
- 基础候选规模：49 个文件，+4,477 / −4,567 行（相对 `3c4a004`，不含最后的进程退出修复及本文）

## ⚠️ 破坏性变更与升级须知

### 1. MCP Python SDK 升级到 2.x

依赖从 `mcp>=1,<2` 改为 `mcp>=2.3.0,<3`，`uv.lock` 固定 `2.3.0`。这不是换用独立的 `fastmcp` 包，仍是官方 SDK。

**升级后必须**：重新同步依赖并重启/重连客户端。常驻服务不会热重载代码。已有论坛索引**无需**删除或重建。

```bash
uv sync --locked
# 然后在客户端重新连接 forum-rag MCP
```

### 2. 知识页不再自动发布

`propose_knowledge_page` 保留旧参数以兼容调用方，但 `auto_publish=True` 与高 `confidence` **不再绕过证据审核**。所有提案一律先成为草稿。

默认知识搜索只复用满足全部条件的页面：已发布 + 审核通过 + 来源版本未变 + 无冲突 + 依赖有效。旧 schema 或未经审核版本的知识页不会进入默认可信检索；读取本身不会偷偷迁移数据库。

新流程：

```text
propose_knowledge_page(..., source_evidence=[...])   # 每项含 topic_id / claim / excerpt
review_knowledge_page(slug, action="reviewed", note="审核依据与适用条件")
publish_knowledge_page(slug)
```

### 3. 独立语义检索产品链路已移除

`62b5b43` / `11b6927` 曾实现离线向量检索与模型下载器（镜像切换、SHA-256 校验、离线缓存）。经实测质量收益不足、内存成本过高（约 930 MiB vs 词法 116 MiB），已由 `c69728d` 整体剥离：专属语义模块、下载器、构建脚本、CLI/MCP 入口均已删除。

- 代码层仍保留可选 `local-embeddings` extra 与兼容基础设施，**不代表**恢复语义 MCP 产品。
- 默认路径无模型下载、无模型加载要求。
- 补充说明：默认 `search_forum` 排序仍使用**确定性哈希特征**（token 哈希向量 + 余弦，权重 dense 0.55 / lexical 0.45）。这是纯 CPU 的特征计算，不加载任何模型权重，与已移除的语义检索不是一回事。
- 跨语言检索改由调用方 AI 提供中英文查询变体完成，工具不自动翻译。

### 4. 仓库不再附带平台官方文档

`Documents/` 中 74 篇平台官方 Markdown 文档已从仓库移除，不再随源码或源码包分发；历史提交同步清理。

- **索引不受影响**：`documents` / `doc_chunks` 表与对应 FTS 记录保持原样，已建立的文档检索照常工作，无需重建。
- **安装步骤变化**：`ingest-docs` 需指向你自己的 Markdown 目录，`ingest-docs Documents` 只在本地仍保留该目录时可用。
- **注意 prune**：`ingest-docs` 默认会删除数据库中「目录里已不存在」的文档。若你指向的新目录不含原有文档，请加 `--no-prune`，否则这些文档记录会被清理。
- 代码与测试不依赖该目录：`src/`、`tests/`、`scripts/` 均无硬编码路径，测试使用临时目录。

## 新增能力

### 批量检索：`search_forum_batch`

一次调用接收原始查询 + 最多 3 个调用方提供的查询变体，分别做有界词法检索，合并排名并按帖子去重。

```python
search_forum_batch(
    query="如何降低换手率",
    query_variants=["reduce turnover", "降低换手率"],
    top_k=6,
    compact=True,
)
```

- 返回：命中查询、语言粗分类、帖子/chunk 标识、内容版本、原文摘录、字符坐标
- 预算：候选 200、SQLite 查询 2 秒、证据按单项 + 总量双重限制
- 原查询中的下划线字段、字母数字混合代码、≥5 位独立数字，在候选截断**之前**下推为字面约束，避免无关候选占满预算
- `compact=True` 省去与 `evidence[].excerpt` 重复的 snippet：实测单例 14,021 → 8,845 字节（约 −37%）

### 相邻证据读取：`get_forum_evidence`

按 chunk ID 展开同一帖子的真实相邻块，可限制前后块数与总字符量，并用 `expected_content_hash` 校验内容是否已变化。保留原文，不把重叠块当作独立证据。

### 安装自检：`forum-rag doctor`

```bash
uv run forum-rag doctor --db /path/to/forum.sqlite3
```

只读检查 Python、SQLite、MCP SDK、数据库文件、论坛与文档来源 schema、FTS 所需列与结构、中文索引状态。输出 JSON + 需用户显式执行的修复建议。**不**创建数据库、不下载模型、不重建索引。

### 可选中文 bigram 候选索引（默认关闭）

```bash
uv run forum-rag search-reindex --db /path/to/forum.sqlite3 --chinese
# 再在服务进程设置 FORUM_RAG_CHINESE_INDEX=1 并重连
```

需要 SQLite ≥ 3.43。候选由 bigram 缩小范围，再以原文字面条件验收；每段连续中文须完整出现，多段为 AND。原 FTS 与排序保留，取消开关即回退原候选路径。索引增加磁盘占用，故不默认启用。

### 评测体系

| 脚本 | 作用 |
| --- | --- |
| `scripts/evaluate_search.py` | 60 条固定题集（44 正例 / 16 负例），记录目标、结果、耗时、源码指纹，支持直调与真实 MCP |
| `scripts/evaluate_relevance.py` | 独立标签、候选排序、跨模式比较，区分 pending / 机器判断 / 人工审核 |
| `scripts/evaluate_task_evidence.py` | 对已保存的任务、回答、调用与证据离线评分，不发起新调用 |
| `scripts/benchmark_concurrency.py` | 分档并发、延迟、吞吐、错误与重复结果一致性 |

## 检索与知识层修复

| 问题 | 处理 |
| --- | --- |
| 无命中退化为无关结果（随机标识符耗时 ~14.9 s，仍返回 5 条） | 区分「正常零命中 / 缺 FTS / FTS 执行错误」三种情况，不再把全量语料交给 Python 打分 |
| ID 精确查找慢（~4.6 s vs 直读 7 ms） | 有效 topic ID 走等值查询，保留社区过滤；不存在的 ID 仍按普通文本查找 |
| `%`、`_`、反斜杠被当作 LIKE 通配符 | 改为字面匹配，`ts_backfill` 不再命中 `tsXbackfill` |
| 旧库（unicode61）中文子串漏召回 | 有界兼容查找 + 可选中文旁路索引，普通读取不重建、不迁移 |
| 内联 `Title:` 标签导致纯中文误标 `mixed` | 仅剥离导出标签，保留标题与正文参与分类 |
| 含 `<`、`>` 的代码比较被 HTML 清理逻辑删除 | 改用保守标签语法保留比较表达式 |
| 小写转换扩展字符长度导致摘录坐标错位 | 归一化命中映射回原文偏移，两条摘录路径共用定位逻辑 |
| 数据库文件被替换后旧连接候选写入新文件缓存 | 打开前后锚定连接身份，不可靠连接绕过跨连接全局缓存 |
| 自有 SQLite 连接未及时关闭（embedding cache、索引入口） | 区分自有连接与调用方传入连接，前者及时关闭 |
| 官方文档 `Operators` 等完整标题排序靠后 | 完整标题优先，新增 `exact_title_match` 标记，`score` 语义不变 |
| 只摄入官方文档的安装被误报整体不可用 | 论坛与文档来源分别检查完整性，`ready` / `degraded` 分级 |
| 非 UTF-8 区域设置下中文评测 JSON 读取失败 | 输入输出显式 UTF-8，不修改评分规则 |

**知识层**同时补齐：`conflicts_with` 冲突双方退出可信复用；`depends_on` 传播依赖失效（`related_to` 不传播）；`supports` / `refines` 支持性入链仅增加排序权重；`action="archived"` 归档并保留原因与替代页，不自动删除或改写其他页面。覆盖长依赖链、环、坏 JSON、元数据与证据边界。

## 资源治理

- **并发名额**：`search_forum_batch` 与 `get_forum_evidence` 共享 2 个工作名额（`read_worker.py`）。满载明确返回 `busy`，不无限排队，也不把资源忙解释为零结果。
- **协作取消**：客户端取消设置取消事件，SQLite progress handler 与 Python 检查点协作退出；名额在底层线程真正退出后才释放。锁等待可能延迟取消。
- **后台任务监管**：`scripts/run_bounded_task.py` 以心跳租约维持所有权，设置总超时、租约过期、退出宽限，按进程组清理后代，并用独立 watchdog 在监督者被强杀后继续清理（限 POSIX）。
- **进程退出竞态修复**：存活探测遇到瞬时 EPERM 时有界重查，只有 ESRCH 才确认进程组消失；持续 EPERM 和发送信号时的权限错误仍显式报错。
- **错误契约统一**：抽取共享的有界读取与错误响应逻辑，`mcp_server.py` 550 → 542 行。

## 已知限制

1. **旧库中文冷查询仍可能慢或超时**：有界 LIKE 避免全量载入 Python，但数据库内部扫描仍有成本；中文索引未默认开启。
2. **无通用语义理解**：本地产品不含独立模型召回，跨语言依赖调用方提供查询变体。
3. **候选有上限，可能漏召回**：多段中文 AND、标识符同块要求、预算限制均有边界；空结果不证明全库无答案。
4. **未完成总体人工准确率验收**：固定目标回归、机器候选判断、合成样例与实际用户任务须分开解释。
5. **取消是协作式的**：锁等待可能延迟退出；2 个工作名额只覆盖两个证据工具，非全局限流。
6. **进程监管仍受系统权限与调度约束**：进程组退出窗口的瞬时 EPERM 已增加有界重查；持续权限错误仍报错，发送信号的权限错误不被忽略。重查共用退出宽限加 50 ms 的截止时间，但不是对系统调度或进程等待的硬实时保证。
7. **跨平台验证不完整**：主要实测环境为 macOS ARM；POSIX 进程监管不适用于所有平台。
8. **语义检索已移除**：历史版本中该功能的性能数据不适用于当前版本。

## 升级步骤

```bash
git fetch --tags && git checkout v0.2.0
uv sync --locked                           # 或 conda 环境内 python -m pip install -e .
uv run forum-rag doctor --db /path/to/forum.sqlite3
```

1. 依赖已同步 → 在客户端重新连接 MCP（旧连接仍运行旧代码）。
2. `doctor` 报告 `degraded` 时按输出建议处理；缺失 FTS 需重建索引。
3. 若使用中文索引：先 `search-reindex --chinese`，再设置 `FORUM_RAG_CHINESE_INDEX=1`。
4. 已有知识页若未经审核版本，将不再进入默认可信检索——需按新流程补充审核。
5. 仓库不再附带官方文档：若你仍需要文档检索，把 `.md` 放到本地任意目录后执行 `ingest-docs <目录>`；要保留数据库中已有文档记录时加 `--no-prune`。

## 回退与数据边界

默认升级不要求数据库迁移。升级前保留原源码，并在停止写入时备份索引；可选中文索引构建、文档摄入和知识写入应单独操作。

如果依赖同步失败、重连后工具发现异常，或既有检索出现回归，停止新服务，恢复原源码与对应依赖后重连。不要直接删除现有数据库；若升级后执行过显式写入，需要按备份评估数据回退，不能假定所有后续写入都可自动降级。
